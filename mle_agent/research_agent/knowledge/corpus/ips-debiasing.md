# Inverse propensity scoring and randomised-exposure validation

Tags: debiasing, evaluation, counterfactual, off-policy

Source: Schnabel et al., "Recommendations as Treatments: Debiasing Learning and
Evaluation", ICML 2016. arXiv:1602.05352

## What it is

Logged recommendation data is not a random sample. Items appear in a log because a
production policy chose to show them, so the training distribution is the policy's, not
the world's. IPS reweights each observation by the inverse of its propensity — the
probability that item was shown — to recover an unbiased estimate:

    weighted_loss = sum_i ( loss_i / propensity_i )

Separately, and often more usefully, some datasets ship a *randomised exposure* log:
impressions generated by showing users uniformly random items. That log is unbiased by
construction and needs no propensity model at all.

## Why it helps a ranking metric

Two distinct uses, and the second is usually the higher-value one.

**As a training correction**: reweighting counteracts popularity bias, where the model
learns "this item is shown often" rather than "this user likes this item".

**As an unbiased validation set**: this is the one worth reaching for first. A model can
improve on biased validation data purely by fitting the logging policy better — learning
what the old system liked, not what users like. If the held-out test distribution differs
from the biased training distribution, that improvement will not transfer, and biased
validation cannot detect the problem because it shares the bias.

Scoring on a randomised-exposure log answers a question biased validation cannot: is this
a real gain or is it policy-fitting? When validation gains stop transferring, this is the
diagnostic that explains why.

## How to implement

**Unbiased validation** is the cheap version and requires no propensity estimation:

1. Load the randomised-exposure log if the dataset ships one.
2. Score it with the trained model and evaluate with the same metric implementation.
3. Track it alongside the primary validation score as a *diagnostic*, not as the
   selection criterion. Selecting on it would change the objective being optimised; the
   value is in watching the gap between the two.

A widening gap — primary validation rising while the unbiased score is flat or falling —
means the model is fitting the logging policy.

**IPS training weights** need propensities, which the dataset usually does not provide.
Estimating them from item frequency is the crude standard:

    propensity_i ∝ item_frequency_i ** alpha        # alpha in [0.5, 1.0]
    weight_i = 1.0 / clip(propensity_i, floor, None)

Clipping the denominator is mandatory. Rare items get enormous weights and a single one
can dominate a batch; the variance of an unclipped IPS estimator is notoriously bad.

## When it will not help

- No randomised log and no propensity information means no reliable way to apply either
  half. Frequency-based propensity estimates are a rough proxy and can hurt.
- IPS weighting increases gradient variance. If training becomes unstable after adding
  it, the clipping floor is probably too low.
- The unbiased-validation use is a diagnostic. It explains failures and catches
  policy-fitting; it does not by itself raise the primary score.
